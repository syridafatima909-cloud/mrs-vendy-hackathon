Features

Built for data you can trust

Four capabilities that make Mrs Vendy's data safe to share and useful to test against. Each panel below runs on the live dataset.

01 · Schema-aware generation

Relationships first, rows second

Mrs Vendy builds the relational skeleton before it simulates anything, then runs one clock over every machine. Keys, stock levels and totals agree by construction instead of being patched afterwards.

  • Declarative schema with primary and foreign keys
  • Demand shaped by site type, hour, weekday and heat
  • Inventory reconciles exactly: start + restocks − vends = end
02 · AI edge-case injection

Describe a failure, get the data

Type what should go wrong in plain English. Mrs Vendy turns it into timed events and simulates their knock-on effects: warm cabinets, locked-out slots, spoiled stock, lost sales and service tickets.

  • Compressor failures, heatwaves, power cuts, demand spikes
  • Card reader outages, open doors, missed restocks
  • Every event is verified in the data afterwards
03 · Data checkpoints

Save a state, reload it exactly

A checkpoint keeps the settings, prompt and event plan. Generation is deterministic, so restoring rebuilds every table and document byte for byte, and a fingerprint proves it.

  • Save, restore, delete, export and import as JSON
  • Fingerprint check on every restore
  • Share a scenario with a teammate as a small file
04 · Feature information

Metadata you can inspect and verify

The schema inspector shows every table's grain, key, lineage and columns, with each constraint checked against the current data as you look at it.

  • Types, primary and foreign keys, ranges, allowed values
  • Cross-table rules, such as amount = qty × unit price
  • Field lineage for every document
The problem

Real fleet data is scarce, sensitive and slow to get

Privacy and compliance

Sales logs carry card data, site contracts and revenue. Teams can't pass them to vendors, share them in the cloud, or use them in demos.

Missing edge cases

A real fleet might see one compressor failure a quarter. Engineers need hundreds of them, with the downstream effects, to test alerts and models.

Slow sign-off

Getting a sanctioned extract for a test suite can take weeks. Synthetic data that behaves like the real thing is available in seconds.

How it works

Schema-aware, simulated together, proven consistent

Most generators fill each table on its own and hope the totals line up. Mrs Vendy builds the relational skeleton first, then runs one clock over every machine, so the tables and documents agree by construction.

  1. Define the schema

    Ten linked tables with primary and foreign keys. Or upload your own CSV and the platform infers types, keys and sensitive columns.

    warehouses → routes → machines machines → slots → transactions

  2. Model the relationships

    Planograms depend on site type, demand follows hour of day and weekday, drivers restock each stop on their route's service days.

    university: peaks 10:00 13:00 16:00 hospital: open 24 h

  3. Simulate and inject edge cases

    Every machine steps through time in 15-minute intervals. Your prompt becomes events: heatwaves, compressor failures, outages, demand spikes.

    "compressor failure on #404 during a heatwave on day 3"

  4. Validate and export

    Around 50 automated checks prove keys resolve, stock reconciles, invoices match sales and no personal data leaks. Then export CSV or JSON.

    start + restocks − vends = end invoice total = Σ vends
